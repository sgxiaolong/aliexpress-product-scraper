# 速卖通商品采集库项目计划

本文保留原计划的阶段与状态，不将文档翻译视为功能验收。

## 原则

- 保持向后兼容，不改变默认行为和输出结构。
- 只增加可选能力，新行为须显式启用。
- 支持 Node 24 及以上版本。
- 使用测试保护输出契约，减少回归。

## 已完成阶段

- 阶段 0（`codex/plan`）：计划文档和基础工作流更新。
- 阶段 1（`codex/test-harness`）：提取辅助函数，建立单元、集成、契约测试和 Node 24 CI。

## 后续里程碑

### 阶段 2：使用体验与性能（`codex/ux-perf`）

状态：[ ]

- 接受商品 URL 或商品 ID，保持相同输出。
- 支持可选浏览器注入，复用 Puppeteer 实例。
- 增加 `fastMode`，跳过描述和评论并阻止大体积资源。
- 区分无效 ID、访问被拦截、超时等错误。
- 移除 node-fetch，使用 Node 24 原生 fetch。

所有新行为须显式启用，默认行为不变。

### 阶段 3：批量采集（`codex/feature/batch`）

状态：[ ]

- 提供 `scrapeMany(idsOrUrls, options)`。
- 支持并发上限、重试和单项超时。
- 提供进度回调或异步迭代器。

保持既有单商品 API 不变。

### 阶段 4：地区选项（`codex/feature/localization`）

状态：[ ]

- 支持 `shipTo`、`currency`、语言/地区选项。
- 根据地区筛选物流输出。

默认行为保持不变。

## 测试策略

- 单元测试：纯辅助函数，无 I/O。
- 集成测试：仅使用固定样本，不联网。
- 端到端测试：显式运行 `ALIX_SMOKE=1 pnpm run smoke`。
- 契约测试：以固定样本的稳定输出快照验证。

## Agent 工作流（Codex 与 Ralph 循环）

每个 PR 使用独立分支；已安排多个 Agent 时分别使用独立 worktree。工作限制在当前阶段内，优先使用项目已有脚本和工作流。
