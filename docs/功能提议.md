# 功能提议

本文记录路线图中三个主要功能的提议，完整里程碑见[项目计划](项目计划.md)。以下是设计与验收目标，文档翻译不改变原有待验收状态。

---

## 1. 支持商品 URL 输入

**阶段：** 2 (codex/ux-perf)
**工作量：** 小 | **影响：** 大

### 问题
用户通常直接复制浏览器中的完整速卖通 URL；要求手动提取数字商品 ID 会增加操作成本，也容易出错。

### 接口设计

```js
import scrape from "aliexpress-product-scraper";

// 现有 ID 用法继续支持
const product = await scrape("1005006543210");

// 新增完整 URL 输入
const product = await scrape("https://www.aliexpress.com/item/1005006543210.html");
```

### 支持的 URL 格式

| 格式 | 示例 |
|---|---|
| `aliexpress.com/item/<id>.html` | `https://www.aliexpress.com/item/1005006543210.html` |
| `aliexpress.us/item/<id>.html` | `https://aliexpress.us/item/1005006543210.html` |
| 移动站 | `https://m.aliexpress.com/item/1005006543210.html` |
| 带查询参数 | `https://www.aliexpress.com/item/1005006543210.html?spm=abc` |

### 实现说明
- 解析输入：包含 `/item/` 时通过正则提取数字 ID。
- 输入已经是数字或数字字符串时直接使用。
- 无法识别的格式抛出明确错误。

### 验收条件
- [ ] 同一商品的 `scrape(url)` 与 `scrape(id)` 输出一致
- [ ] 所有支持的 URL 格式均能正确解析
- [ ] 无效 URL 返回清楚的错误说明
- [ ] 现有数字 ID 用法不受影响，保持向后兼容
- [ ] 单元测试覆盖 URL 解析逻辑

## 2. `fastMode` 快速模式

**阶段：** 2 (codex/ux-perf)
**工作量：** 中 | **影响：** 大

### 问题
快速查询商品的用户通常只需要标题、价格、变种和图片等基本信息；完整描述页与评论接口会增加采集耗时。

### 接口设计

```js
import scrape from "aliexpress-product-scraper";

const product = await scrape("1005006543210", { fastMode: true });

// product.description === null
// product.reviews === []
```

### 快速模式下的字段变化

| 字段 | 普通模式 | 快速模式 |
|---|---|---|
| `title`, `productId`, `categoryId` | 正常填充 | 正常填充 |
| `quantity`, `orders` | 正常填充 | 正常填充 |
| `storeInfo`, `ratings` | 正常填充 | 正常填充 |
| `images`, `variants`, `specs` | 正常填充 | 正常填充 |
| `originalPrice`, `salePrice` | 正常填充 | 正常填充 |
| `currencyInfo`, `shipping` | 正常填充 | 正常填充 |
| `description` | HTML 字符串 | `null` |
| `reviews` | 评论数组 | `[]` |

### 性能优化
- 跳过描述 iframe 或页面导航
- 跳过评论接口及其所有分页
- 使用 Puppeteer 的 `page.setRequestInterception` 阻止图片、字体和样式表等较大资源
- 原提议预期提速 50–70%，属于待实测目标

### 验收条件
- [ ] `fastMode: true` 跳过描述和评论采集
- [ ] 输出字段结构不变，描述为 `null`、评论为 `[]`
- [ ] 实测证明资源拦截减少页面加载时间
- [ ] 不设置 `fastMode` 或设为 `false` 时默认行为不变
- [ ] 单元测试验证快速模式的字段和值

## 3. 使用 `scrapeMany()` 批量采集

**阶段：** 3 (codex/feature/batch)
**工作量：** 大 | **影响：** 大

### 问题
批量业务需要采集几十到几百个商品。逐个调用 `scrape()` 较慢，直接无限并发又可能导致浏览器崩溃或触发限流。

### 接口设计

#### 回调方式

```js
import { scrapeMany } from "aliexpress-product-scraper";

const results = await scrapeMany(
  ["1005006543210", "1005006543211", "1005006543212"],
  {
    concurrency: 3,        // 最大并行标签页数，默认 2
    retries: 2,            // 单商品失败重试次数，默认 1
    timeout: 30000,        // 单商品超时毫秒数，默认 60000
    fastMode: false,       // 应用于全部商品
    onProgress: ({ completed, total, productId, success }) => {
      console.log(`${completed}/${total} done`);
    },
  }
);

// results: Array<{ productId, data, error }>
```

#### 异步迭代方式

```js
import { scrapeMany } from "aliexpress-product-scraper";

for await (const result of scrapeMany(ids, { concurrency: 3 })) {
  if (result.error) {
    console.error(`Failed: ${result.productId}`, result.error);
  } else {
    console.log(`Got: ${result.data.title}`);
  }
}
```

### 设计决策
- **浏览器复用：** 启动一个浏览器，通过多个页面并行采集
- **并发控制：** 活跃页面数量不超过 `concurrency`
- **重试：** 按商品独立重试，使用指数退避
- **超时：** 按商品独立计时，不影响其他商品
- **错误隔离：** 单商品失败不终止整个批次
- **返回格式：** 每项包含 `{ productId, data, error }`，便于调用方处理部分失败

### 验收条件
- [ ] `scrapeMany()` 并行采集多个商品
- [ ] 并行页面不超过 `concurrency`
- [ ] 失败商品最多重试 `retries` 次
- [ ] 单商品超时会终止该项，不影响其他商品
- [ ] 每项完成后触发 `onProgress` 回调
- [ ] 异步迭代器按完成顺序产出结果
- [ ] 全批次复用浏览器，完成后关闭
- [ ] 原有 `scrape()` API 保持不变
- [ ] 使用固定样本的集成测试验证批次编排逻辑
